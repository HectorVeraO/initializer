# Glossary

Terms used across initializer, its module catalog and the generated projects. Rules live in `AGENTS.md`; this file only says what a word means and where the thing lives.

| Term | Meaning | Where |
|---|---|---|
| Active tenant | The tenant a session is working in. It comes only from the session token or the API key, never from the request body or path; every `:id` access filters by it, and another tenant's resource answers `404`. The console sends it back as `X-Active-Tenant-Id` so a stale tab gets `409 ACTIVE_TENANT_CHANGED`. | `go-srv/internal/platform/core/access/` |
| API key (M2M) | A machine-to-machine credential for one tenant, sent as `X-API-Key`, with scopes (`tenant:read`, `api-keys:read`). The plain key is shown once at creation; only its prefix is stored readable. | `go-srv/internal/platform/identity/apikeys.go` |
| BFF session | The stateless browser session: go-srv signs a short-lived token in the `app_session` cookie after a Kratos login, refreshes it from the Kratos session, and checks `X-XSRF-TOKEN` against the `XSRF-TOKEN` cookie on every write. No session table exists. | `go-srv/internal/platform/identity/session/` |
| Catalog | Every module, spec and owned file of this repo, with hashes, built from the manifests into `catalog.lock.json` (in CI, never committed). The generator reads only the catalog. | `initializer catalog build` |
| Composition root | The one file per stack that lists the selected modules: `go-srv/cmd/server/modules.go` and `ng-web/src/app/platform/modules.ts`. The generator renders it; nothing else imports a module folder. | `tooling/generator/internal/render/` |
| Contract | A module's HTTP API as `specs/<module>/openapi.yaml`. Error and issue codes are open lists (`x-extensible-enum`); a breaking change needs a MAJOR bump and a `BREAKING CHANGE:` trailer. | `specs/<module>/` |
| Copy-and-own | A generated project receives the module code as plain files at the same paths and owns it from then on; `initializer.lock.json` records the base version and hashes so later updates can see what was edited. | `initializer.lock.json` |
| `core` / `identity` | The two modules every project gets: `core` (envelope, errors, telemetry, health, database, the module seam) and `identity` (Kratos identity, BFF session, tenants, memberships, invitations, API keys). | `go-srv/internal/platform/{core,identity}/`, `ng-web/src/app/platform/core/` |
| Envelope | The shape of every `/api/v1/` response: `{ data, meta: { traceId, timestamp }, error }`. Invalid input answers one `422 VALIDATION_FAILED` with every problem in `error.issues[]`. | `go-srv/internal/platform/core/api/` |
| Feature flag | A boolean declared in `flags.yaml` with `type: release` (temporary, `default: false`, expires within 30 days) or `type: ops` (permanent kill switch). Value: tenant override, else global override, else the manifest default; an unknown key is `false`. | `flags.yaml`, `go-srv/internal/platform/featureflags/` |
| Gates | Repo checks the CI job `gates` runs: `flags` (`flags.yaml` rules), `migrations` (file names, table prefixes), `contracts` (breaking changes with oasdiff), `versions` (manifest bumps, tags). | `tooling/gates/` |
| Generator | The `initializer` CLI: `catalog build`, `generate`, `verify --project`. Output is deterministic: the same catalog and selection give the same bytes. | `tooling/generator/` |
| `initializer.lock.json` | Written into every generated project: the selection, each module's base version, and the hash of every delivered file. `initializer verify --project <dir>` reports files that were modified, are missing or were added inside module folders. | generated project root |
| `initializer.selection.json` | The input of a generation: project name, Go module path, stacks and modules. A generated project carries its own, so generating again from it reproduces the tree byte for byte. | `tooling/generator/testdata/ci/` (examples) |
| Kratos | Ory Kratos, the identity provider (passwords, login flows). go-srv proxies its browser flows under `/kratos/` so the console has one origin. | `.deploy/local/kratos/` |
| Module | One composable capability with a `module.manifest.json` per stack (id, version, files it owns, specs it implements, modules it requires). | `go-srv/internal/platform/<module>/`, `ng-web/src/app/platform/<module>/` |
| Module catalog | The catalog of composable modules that initializer generates projects from. | `go-srv/internal/platform/`, `ng-web/src/app/platform/`, `specs/` |
| Parameter | A typed setting (`string`, `number`, `boolean`, `json`) with optional range or allowed values. Value: the tenant override if one exists, else the global default value; `source` (`tenant` or `global`) says which. | `go-srv/internal/platform/parameters/` |
| Platform operator | An account that may manage tenants and feature flags across tenants: the Day-0 bootstrap admin plus the addresses in `APP_PLATFORM_OPERATOR_EMAILS`. | `go-srv/internal/platform/identity/bootstrap.go` |
| Role | A member's role inside one tenant: `admin`, `member` or `viewer`. | `go-srv/internal/platform/core/reqctx/` |
| Round trip | Generating every module of this repo and comparing the output with the repo's own files; any difference means the generator would not reproduce the catalog. CI job `generator`, local gate `generator-roundtrip`. | `.github/workflows/ci.yml` |
| Spec manifest / tags | `specs/<module>/spec.manifest.json` holds the contract version and its TCK tags; CI on `main` tags every new version as `spec-<module>-vX.Y.Z` (and modules as `<stack>-<module>-vX.Y.Z`). | `specs/<module>/`, `.github/workflows/tags.yml` |
| Stack | One implementation language of the catalog, named by its folder: `go-srv` (Go backend) and `ng-web` (Angular console). | repo root |
| TCK | Technology Compatibility Kit: the black-box Playwright suite in `specs/<module>/tck/` that certifies an implementation against the module's contract, over HTTP only, so any stack can be certified. Tags `@core`, `@identity`, `@parameters`, `@feature-flags` and `@otel` select a module's scenarios; a generated project runs the tags its lock selects. Run: `TCK_BASE_URL=http://localhost:10100 npm --prefix specs run tck`. | `specs/`, CI jobs `tck` and `generated-project` |
| Tenant | An organization inside one installation. People belong to tenants through memberships (with a role) and join through invitations. | `go-srv/internal/platform/identity/` |
| Trace correlation | Every request continues or opens a W3C `traceparent` trace; logs and spans carry `trace_id`, `span_id`, `tenant_id`, `actor_id`; the `X-Trace-Id` response header equals `meta.traceId`. | `go-srv/internal/platform/core/telemetry/` |
| Trunk-based development | Everything merges to `main` behind small PRs: no flag on a fix, persistence and domain first and unreachable, one release flag only on the PR that exposes the route, and a cleanup PR that deletes the flag. | `go-srv/cookbooks/tbd-feature-flags.md` |
